    EVERYO / FEATURES

    Explore the framework

    A practical map of EveryO’s components, with optional integrations and validation limits stated clearly.

    Tensor Computing

    Public tools include eo.tensor, matmul, reshape, reductions, and NumPy conversion. Tensor properties expose shape, dtype, device, and gradient state.

    Read the reference →

    Automatic Differentiation

    requires_grad records supported operations; backward propagates derivatives. no_grad skips recording during inference. The project checks gradients against finite differences.

    Read the reference →

    Neural Network Components

    Sequential and Module compose Linear, Conv2D, pooling, normalization, recurrent, and attention components. Image tensors use NHWC layout.

    Read the reference →

    Optimization and Training

    Trainer combines models, optimizers, losses, data loaders, metrics, and callbacks. Available optimizers include SGD and Adam.

    Read the reference →

    Backend Integration

    The core is CPU-first on NumPy. CUDA needs the optional native extension, NVIDIA toolchain, and suitable hardware; GPU tests skip in the project’s CPU-only CI. TensorFlow provides optional reference comparisons.

    Read the reference →

    Testing and Developer Tools

    Use everyo doctor for installation diagnostics. The repository includes tests, headless visualization, optional profiling, and ONNX export. Review export shape limitations before using another runtime.

    Read the reference →

    Implemented is not the same as production-validated.

    EveryO is intended for learning and small-scale experiments. Multi-node behavior is tested across processes, not separate physical machines. Optional CUDA requires validation on real GPU hardware. Quantization is a size/fidelity trade, not a claimed speedup.
