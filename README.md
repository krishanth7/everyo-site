# EveryO — public website

The source of the EveryO project site: a single static page explaining what
EveryO is, what it can do, what has been verified, and how the project is
governed.

**Live site:** https://krishanth7.github.io/everyo-site/
**The framework itself:** https://github.com/krishanth7/EveryO

---

## What this is

One page, no build step, no framework, no package manager. Open `index.html`
in a browser and it works. That is deliberate: a site describing a project
whose whole argument is legibility should itself be readable end to end.

```
index.html              the entire page
assets/css/styles.css   design tokens, layout, light and dark themes
assets/js/site.js       ~85 lines: mobile menu and theme toggle. Nothing else.
assets/img/             figures generated by EveryO itself, copied from the framework repo
.nojekyll               tells GitHub Pages to serve the files as they are
robots.txt, sitemap.xml
llms.txt                a plain-text summary for language models, including the limits
humans.txt, cats.txt, ads.txt, .well-known/security.txt
```

### Deliberate constraints

- **No analytics, no cookies, no third-party scripts.** The framework collects
  no telemetry; a site that tracked its readers would contradict it. The only
  external request is the Google Fonts stylesheet.
- **No JavaScript framework.** The page renders fully without JavaScript; the
  script only adds the mobile menu and the theme toggle.
- **Every number on the page is measured.** Test counts, timings, accuracy
  figures and the TensorFlow comparison deltas come from real runs in the
  framework repository. There are no invented download counts, star counts or
  benchmark claims.

## Typography

The page is set entirely in [Google Sans Code](https://fonts.google.com/specimen/Google+Sans+Code),
a monospace variable font, loaded with `MONO` at `1` and optical sizing on:

```css
font-family: "Google Sans Code", ui-monospace, monospace;
font-optical-sizing: auto;
font-variation-settings: "MONO" 1;
```

A fallback stack of system monospace fonts sits behind it, so the layout holds
if the webfont is blocked.

## Running it locally

No dependencies:

```bash
python3 -m http.server 8000
# then open http://localhost:8000
```

## Deploying

The site is served by GitHub Pages from the repository root of the default
branch.

1. **Settings → Pages**
2. **Source:** *Deploy from a branch*
3. **Branch:** `main`, folder `/ (root)`
4. Save. The first build takes a minute or two.

`.nojekyll` is present so Jekyll does not reprocess the files.

### Updating the figures

The images in `assets/img/` are produced by the framework, not drawn by hand.
To refresh them, run the examples in the EveryO repository and copy the output:

```bash
# in the EveryO checkout
python examples/neural_network.py
python examples/convolutional_network.py
python examples/sequence_models.py
cp docs/assets/*.png ../everyo-site/assets/img/
```

If an image's dimensions change, update the `width` and `height` attributes on
its `<img>` tag too — they are there so the browser reserves the right space
and the page does not shift while images decode.

## Browser support

Checked in Chromium at **twelve widths from 320px to 1440px**, in both colour
schemes. At every one of them `document.scrollWidth == clientWidth`, so the page
never scrolls sideways; the tables and code blocks scroll inside their own
containers instead.

Three real layout bugs were found that way and fixed rather than described:

| Width | Symptom | Cause |
|---|---|---|
| 901–1100px | Page ~300px wider than the viewport | Nine nowrap nav links did not fit, but the menu breakpoint was 900px. Raised to 1150px, where the items actually run out of room |
| 320px | Page 7px too wide | `init_tcp_process_group` has no break opportunity. Inline `code` may now wrap; `pre code` still does not |
| ≤380px | Header cluster overflowed | The GitHub button's label now gives way; its icon remains |

Uses `color-mix()` and `backdrop-filter`, which degrade gracefully on older
engines — the header simply becomes opaque.

## Keeping the page honest

Every figure on the page is measured in the framework repository, and the two
are easy to drift apart. When EveryO changes, these need re-checking:

- The three hero statistics (gradient-engine lines, package size, test count).
- The traced-export table in **Interoperability** — regenerate with
  `python examples/onnx_trace.py` in the EveryO checkout.
- The **verification matrix** under Roadmap, which states for each recent item
  what was checked *and what was not*. The GPU and multi-node rows say plainly
  that no GPU and no second machine exist in CI. If that ever changes, the rows
  change with it — they are not decoration.
- `llms.txt`, which repeats the same numbers and the same limits for machine
  readers.
